# 开发笔记：把待办变成会开花的小花园

## 为什么这样做

待办列表很实用，但普通的勾选反馈比较单调。这里把任务映射成植物：添加时是芽，完成后开花，撤销完成又变回芽。像素场景用 Canvas 的矩形直接画出，无须下载图片或引入绘图库。

## 两层代码

`core.js` 管规则，`app.js` 管页面。

规则函数接收旧状态、返回新状态，不直接碰 DOM 和浏览器存储。这样能用 Node 的内置测试工具检查计时、完成统计与备份数据。

页面层负责显示任务、画花园、绑定按钮和保存状态。任务名称使用 `textContent`，不会把输入内容当成 HTML 执行。

## 计时不是每秒减一

运行时保存一个结束时间 `deadline`，显示的剩余时间由 `deadline - 当前时间` 得出。后台页面可能被浏览器降低执行频率；重新打开或回到页面时，重新计算就能追上进度。

暂停时存下剩余毫秒，清掉结束时间；继续时，根据剩余毫秒计算新的结束时间，保留原来的这一轮编号。

计时到期由 `advance()` 结算一次，增加累计分钟并回到空闲状态。最近完成的计时编号也保留在状态中，避免同一编号被重复记账。

重置未完成的一轮不会奖励分钟；已经到期的一轮则先结算，再重置。

## 本地保存与备份

状态使用 `localStorage`，每次有效操作后保存。页面会接收同一来源的存储变化，在其他标签页更新后同步显示；同时编辑多个标签页仍采用浏览器最后一次写入的状态，建议集中在一个标签页操作。

导出与导入使用同一种版本为 1 的 JSON 格式。导入前检查任务数量、编号是否重复、标题长度、时间、计时状态和累计记录；通过后才询问是否替换原有数据。

若原有记录损坏，页面会进入临时模式，保留原始存储内容；此时导出会保留无法读取的原始记录，便于后续恢复。存储写入失败时也会显示实际错误状态，提醒用户保存备份。

## 为什么能直接双击

脚本使用普通的 `defer` 引用，数据层同时兼容浏览器全局对象与 Node 的 CommonJS。没有使用需要 HTTP 服务才能稳定载入的 ES Module，也没有访问本地文件的 `fetch()`。

因此同一份规则代码可以用于浏览器和测试，直接从 `file://` 打开也能工作。

## 测试里最值得看的几处

- 暂停 100 秒再继续，不应该平白消耗专注时间。
- 旧的运行状态在刷新恢复时已经到期，只补记一次。
- 任务完成后重复勾选，不改变首次完成时间。
- 备份数据畸形或任务编号重复，不能覆盖当前记录。
- 输入看起来像 HTML 的任务标题，也只显示成文字。
- 桌面和手机页面都不能产生横向滚动。

浏览器检查直接使用已安装的 Chrome / Edge 和其 DevTools 协议，没有第三方测试依赖。检查会打开独立的隐藏浏览器配置，不读取日常浏览器里的个人记录。
